# 目录与职责拆分实施说明

## 本阶段目标

将代码仓库、构建收件目录、运行目录、发布归档、日志和数据库数据目录分开；不迁移业务数据，不变更数据库 schema，也不改变 API 行为。

## 目录职责

| 路径 | 职责 | 可否写入业务数据 |
| --- | --- | --- |
| `/root/duban` | Git 仓库和部署脚本 | 否 |
| `/opt/duban/incoming` | CI 或本地部署上传的构建产物 | 否，部署完成后可覆盖 |
| `/opt/duban/releases/<release-id>` | 本次发布前后端构建快照 | 否 |
| `/opt/duban/server` | 宿主机 Node/PM2 运行目录和私有 `.env` | 仅运行配置、日志引用 |
| `/var/www/duban` | Nginx 托管的前端产物 | 否 |
| `/var/log/duban` | 部署日志 | 是，日志 |
| `/srv/duban-data/mysql` | Docker MySQL 持久化数据的目标目录 | 是，数据库数据 |

## 部署行为

`deploy/deploy-local.sh` 将前端和后端构建产物上传到 `/opt/duban/incoming`，部署控制脚本仍从 `/root/duban/deploy` 启动。`deploy/deploy-server.sh` 为本次构建创建 `/opt/duban/releases/<release-id>` 快照，然后更新宿主机或容器运行时。

为兼容尚未完成切换的旧服务器，远端脚本在收件目录为空时回退读取 `/root/duban/dist` 和 `/root/duban/server/dist`。确认新路径稳定后，可另行安排删除旧构建目录的迁移窗口；本次改动不会删除任何远端目录或数据。

## 上线前准备

1. 在服务器创建 `/opt/duban/incoming`、`/opt/duban/releases`、`/var/log/duban` 和 `/srv/duban-data/mysql`，按运行账号设置权限。
2. 保持私有环境文件位于 `/opt/duban/server/.env`，权限为 `600`，不要复制到仓库、收件目录或 release 目录。
3. Docker 默认继续使用既有 `mysql_data` named volume。完成备份、恢复演练和迁移后，才可在 `.env` 中将 `DUBAN_MYSQL_DATA_ROOT` 改为 `/srv/duban-data/mysql`；直接切换挂载会初始化空库。
4. 首次发布后确认 `/api/health` 的 releaseId、PM2 工作目录、Nginx 静态目录和 MySQL 数据目录均指向预期位置。
