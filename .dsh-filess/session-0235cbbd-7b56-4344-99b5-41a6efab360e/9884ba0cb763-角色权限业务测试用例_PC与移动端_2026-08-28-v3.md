## 一、关键代码事实与口径（用例设计依据，按当前源码）

### 1.1 角色→身份映射与三层权限

- 前端 `UserRole` 三值映射 `mapRoleIdentityToUserRole`（`src/store/role-access.ts:62-71`）：roleIds 含 `r1/r4dtsn6m`→ADMIN；含 `r2`→FOLLOWER；**其余（r3、r6、r5）→OWNER**。
- 服务端 `getUserRoleKind`（`server/src/lib/item-scope.ts:288-298`）：仅 r1/r4dtsn6m（或旧角色名）→`'ADMIN'`。
- 三层权限：菜单/路由（`ProtectedRoute`，`src/components/Common/ProtectedRoute.tsx:27-31`，判定顺序 登录→allowedRoles→authCode→extraCheck）；按钮动作（前端 `canUsePageAction` vs `canUseAllowedAction` 双口径，`role-access.ts:86-121`；服务端 `hasPageAction` 四级 + `canUseItemAction`，`server/src/routes/page-actions.ts:95-114`、`items.policy.ts:145-172`）；行级数据（`buildItemAccessWhere` SQL 下推 + `filterItemsByAccess` 内存复核，`server/src/routes/access.policy.ts:477-539/371-418`）。
- 行级身份校验核心 `ensureItemActorAllowed`（`server/src/routes/items.ts:615-693`，`hasGlobalPrivilege` 定义于 `:603`）：SIGN/FEEDBACK/DELAY 仅责任人；URGE/CHANGE/SUSPEND/RESTART/DISABLE/REJECT/MARK_UNSATISFIED/DELETE 仅跟进人；APPROVE 跟进人或其直属上级（`hasGlobalPrivilege` 对 APPROVE **不豁免**，`items.ts:677-683`）；APPLY_COMPLETE/SHARE 相关人员。
- 回收站归属：非管理员仅能操作 `deletedById===自己` 的事项（`items.ts:1470-1475、2261-2266`）。
- `isDeptManagerLike`（`access.policy.ts:151-158`）只扩大数据范围（本部门+子部门+汇报链下属+自定义人员），**不授予写操作**。

### 1.2 本版相对 v2 的行为变更（交叉验证重点）

1. **单责任人终审（DF-1 已修）**：终审后状态取 `resolveFinalApprovalStatus`——无活动子任务（单责任人事项）终审即整体 COMPLETED 且补写 `actualCompletionDate`（`server/src/lib/item-effective-status.ts:44-54`、`server/src/routes/items.ts:1710-1714`）；有子任务时维持最差状态聚合。
2. **驳回放行（DF-2 已修）**：`rejectReason` 移出 GENERAL_EDIT_FIELDS，不再触发 CHANGE_ITEM（`server/src/routes/items.policy.ts:331-337`），「我的督办」（MENU_MY_ITEMS 上下文）与移动端详情驳回不再被 pageSupportsAction 拦截。
3. **签收计划日期口径统一**：有 `requiredCompletionDate`（要求完成日期）时前后端均直接按其签收、不做"不早于今天"拦截、责任人不可覆盖（后端 `getPlannedCompletionDateForSign`，`items.ts:137-163`；PC 详情 `src/pages/Items/Details.tsx:258-264,652-691`；PC 我的督办 `src/pages/MyItems/index.tsx:146-224`）。
4. **多责任人延期父级保护**：任一责任人延期只写本人子任务日期；父级 plannedCompletionDate/deadline 取全部子任务计划日期**最晚值**（`items.ts:1926-1938` + `getLatestSubTaskPlannedDate`，`items.ts:104-122`）。
5. **催办**：单条接收人=子任务责任人 ∪ 根级责任人 ∪ 跟进人（`collectSingleUrgeTargets`，`server/src/routes/urge.ts:129-134`）；幂等键超 64 字符折成 sha256（`normalizeUrgeIdempotencyKey`，`urge.ts:36-38`；移动端键格式 `urge_<itemId>_<receiverId>_<requestId>_<index>`，`src/lib/mobile-urge.ts:24`）；时间轴/消息写中文方式名（`describeUrgeMethod`，`urge.ts:41-47`），历史英文枚举由前端兜底替换（`formatUrgeTimelineContent`，`src/lib/item-format.ts:238-250`）；行级过滤前做 TEXT 列 JSON 规整+身份回填（`urge.ts:245-247、369-371`）。
6. **移动端消息分类与 PC 对齐**：待办/催办/通知 Tab 只显示未读，已读归入「已读」Tab（`src/pages/Mobile/Messages.tsx:44-53`）。
7. **移动端剩余天数统一口径**：`computeRemainingDays`（`src/lib/remaining-days.ts:33-54`）——基准优先要求完成日期、DELAYED 状态回退 deadline、到期当天=1、OVERDUE 至少超期 1 天；列表卡片与详情共用。**例外**：首页「高频待办」排序仍用简化 `deadline` 天数且不含当天（`src/pages/Mobile/Home.tsx:80-85`）。
8. **登录身份显式落盘**：`writePersistedIdentity`（`src/store/useStore.ts:191-199、627`）解决 persist 不生效导致的身份恢复不一致；**但移动端退出登录仍只清 token 不清 `duban-storage`**（`src/pages/Mobile/Mine.tsx:60-68`；store `logoutUser` 清双 key，`useStore.ts:646-647`）。
9. **移动端「我的」新增修改密码**（`Mine.tsx:70-95、193-245` → `api.auth.changePassword`，`server/src/routes/auth.ts:84`；PC 端无此入口）。
10. **移动端 Tab 可见性**：待办 Tab 对纯跟进人隐藏、督办 Tab 对纯责任人隐藏（`src/pages/Mobile/Layout.tsx:39-47`）；但 `/m/supervision` 路由放行 ADMIN/FOLLOWER（`src/App.tsx:82`），`/m/todo` 放行全部三身份（`App.tsx:81`）——Tab 隐藏 ≠ 路由拒绝。
11. **移动端反馈 Modal 已移除进度选择**（`src/pages/Mobile/components/modals/FeedbackModal.tsx:11-52`），与 PC 反馈口径（内容+附件）对齐。

### 1.3 v2 遗留疑点/缺陷（修复状态未确认，用例按行为观察口径覆盖）

- **DF-3**：`MARK_UNSATISFIED_ITEM` 不在 MENU_ITEMS 页面目录，台账进入的「未按要求完成」按钮可见但操作 403（`page-actions.ts` 目录）。
- **DF-4**：无子任务事项 OVERDUE 后可直接反馈且状态回 EXECUTING（拦截仅查本人子任务，`items.ts:649-655`）。
- **DF-5**：终审兜底仅认 `users.role === 'ADMIN'` 字符串（`items.ts:402-428`），中文角色名的 r1 账号不被识别。
- **DF-6**：无要求日期事项签收，API 直传过去的 `plannedCompletionDate` 被接受落库（`items.ts:137-163` 仅校验非空）。
- **DF-7**：批量导入接受停用账号为责任人（`items.ts:1050+` 不校验 status，单条创建 `:909-913` 校验）。
- **DF-8**：部门 parent 成环被接受（`departments.ts:58-73` 无环校验）。
- **DF-9**：r3 侧边栏可见「统一台账/催办管理」但路由被拒进「无访问权限」页；服务端 `/api/urge` 实际放行 200（`Sidebar.tsx:102` vs `App.tsx:62,64`）。

## 十二、执行建议与未覆盖项

1. **执行顺序**：先跑 DF-1/DF-2 回归（SA-02、FO-02、XP-05、EN-01~03）确认修复有效；再跑 XP 交叉矩阵；最后跑观察类（DF-3~DF-9）记录当前行为。

4. **未覆盖/需补充**：
